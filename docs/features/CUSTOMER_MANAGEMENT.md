# Customer Management & Ledger

This document describes how SmartKhata manages customer records, credit (udhaar), and transaction history.

---

## 👤 Customer Profiles

Each customer record stores:

- **Identification**: Name and unique Phone number.
- **Contact Details**: Optional Email and physical Address.
- **Financial Status**: `balance_due` (Real/Rupees).

### 1. Database Schema (`customers` table)

```sql
CREATE TABLE customers (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL,
  phone TEXT UNIQUE NOT NULL,
  email TEXT,
  address TEXT,
  gstin TEXT,              -- B2B Billing (Pro Feature)
  balance_due REAL DEFAULT 0,
  created_at TEXT DEFAULT CURRENT_TIMESTAMP,
  updated_at TEXT DEFAULT CURRENT_TIMESTAMP
);
```

### 2. Balance Interpretation:

- **Positive Balance (`+ ₹X`)**: The customer owes money to the shop (Credit/Udhaar).
- **Negative Balance (`- ₹X`)**: The customer has paid in advance or has a credit note (Advance).

### 3. Crockford Base32 Referral System

SmartKhata implements a built-in referral system tied directly to the Customer ID.

- To prevent easily guessable sequential IDs (like `1`, `2`) while remaining offline, the system converts the integer `id` into a **Crockford Base32** encoded string (e.g., `C3Q`).
- This generated "Secret Code" is printed on thermal receipts. Customers can share this short, human-readable code to earn cashback on future purchases without needing complex online JWT tokens.

## 📒 The Ledger System

The ledger is a chronological record of all financial interactions with a customer.

### 1. Atomic Entries

Whenever a bill is generated or a payment is received, a ledger entry is created **atomically** using the transaction manager within `CustomerService`. This guarantees that the aggregated `balance_due` on the customer card exactly matches the mathematical sum of the ledger entries.

### 2. Schema (`customer_ledger` table)

```sql
CREATE TABLE customer_ledger (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  customer_id INTEGER NOT NULL,
  bill_id INTEGER,          -- Nullable (used for direct payments)
  transaction_type TEXT,    -- SALE, PAYMENT_IN, PAYMENT_OUT, REFUND
  amount REAL NOT NULL,     -- The transaction amount
  balance_after REAL,       -- Running total snapshot for historical integrity
  notes TEXT,
  created_at TEXT DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (customer_id) REFERENCES customers(id),
  FOREIGN KEY (bill_id) REFERENCES bills(id)
);
```

### 3. Entry Types:

1. **SALE**: Created by `BillingService.finalizeBill()` when a bill is generated. Links directly to the `bill_id`.
2. **PAYMENT_IN**: Created by `CustomerService.settleBalance()` when a customer pays their pending udhaar.
3. **PAYMENT_OUT**: Created if the shop issues a refund or payout to the customer.
4. **REFUND**: Generated by `CreditNoteService` when items are returned and the refund is credited to their account rather than paid in cash.

## 💳 Billing Integration (Udhaar Flow)

When finalizing a bill via `BillingService.finalizeBill()`, the system calculates the delta:

1. **Full Payment**: `paymentReceived == grandTotal`. Balance remains unchanged.
2. **Partial Payment**: `paymentReceived < grandTotal`. The shortage (Udhaar) is calculated. The system invokes `CustomerService.updateBalance(+shortage)` and creates a `SALE` entry in the ledger.
3. **Advance/Over-payment**: `paymentReceived > grandTotal`. The extra amount invokes `CustomerService.updateBalance(-advance)` and is recorded.

## 💸 Settling Udhaar (The Payment Flow)

When a customer returns to pay their outstanding balance:

1. The user clicks "Settle Balance" in the `CustomersPage.tsx` UI.
2. The UI triggers `window.electron.customers.settleBalance({ customerId, amount })`.
3. **Backend Logic**:
   ```typescript
   // CustomerService.ts -> settleBalance()
   db.transaction(() => {
     // 1. Deduct from balance_due
     const newBalance = customer.balance_due - amount;
     updateBalance(customerId, -amount);

     // 2. Insert PAYMENT_IN record with the snapshot
     insertLedgerEntry({
       customer_id: customerId,
       type: 'PAYMENT_IN',
       amount: amount,
       balance_after: newBalance,
       notes: 'Balance Settlement',
     });
   });
   ```
